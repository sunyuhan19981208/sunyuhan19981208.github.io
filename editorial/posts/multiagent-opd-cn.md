一个团队最后答错了，不代表每个成员都做错了。搜索子智能体可能找到了关键材料，只是协调者没有选中，或者回答者没有用好。如果把同一个“答错了”的分数发给整条链路，搜索过程很难知道下一次该怎么改。

MultiAgent-OPD 从这个反馈错位出发：协调者和回答者继续学习最终结果，搜索子智能体则在自己真正走过的轨迹上接受教师逐 token 的反馈。这里展开我们为什么这样拆、两阶段训练怎么接起来，以及实验结果里值得一起看的收益和代价。

## 团队变复杂以后，最终奖励就绕远了

我们研究的是 Leader–Searcher–Answerer 结构。Leader 拆分问题，把子任务分发给多个 Searcher；Searcher 检索、读材料、整理报告；Leader 可以再开一轮搜索，最后选出报告交给 Answerer 回答。与固定的“搜一次再回答”相比，这个结构能根据已经找到的证据继续分工。

<!-- image:multiagent-opd:images/method_overview.svg | Leader 多轮分派搜索任务。Searcher 使用教师提供的 OPD 反馈，Leader 和 Answerer 使用结果奖励；三个角色共享一个学生模型。 -->

这种灵活性也拉长了搜索动作与最终答案之间的距离。一份报告是否有用，要经过后续选择和推理才能体现。用最终答案评分，反馈来得晚，而且一条团队轨迹中的不同搜索者可能拿到完全一样的优势值，难以区分谁找到了关键证据、谁只是重复检索。

组相对训练还有一个边界：同一问题的多条轨迹如果全部答对，或者全部答错，结果奖励没有组内差异，相应优势值就会消失。但这些轨迹中的搜索词、补查动作和报告质量仍可能很不一样。我们不希望这部分学习机会完全依赖最终答案是否刚好拉开差距。

另一条路是给搜索报告加 LLM Judge。它能提供局部评分，不过质量取决于评审自身的判断，而且一个报告分数仍然覆盖了前面整串动作。MultiAgent-OPD 尝试换一种局部信号：先训练一个会搜索、会总结的教师，让它在学生当前的上下文里评价学生实际生成的 token。

## 先在简单链路里练好教师

第一阶段不直接训练复杂团队，而是使用 Searcher–Answerer 串联流程。Searcher 拿到原问题，查询固定检索器并写出报告，Answerer 直接依据报告回答。这样，搜索证据与答案之间的联系更短，比较适合先用正确性奖励学习。

两个角色共享模型参数。训练时每次回答请求生成 5 个候选答案，每个候选有自己的归一化 Exact Match 得分；只要其中至少一个候选正确，这条轨迹的团队结果奖励就为 1。Searcher 主要拿结果奖励，另外获得一小部分行为奖励。

<!-- equation:opd-stage-one -->

行为项在搜索一次后给出总结时为 0.5，搜索两次及以上再总结时为 1，否则为 0；格式无效的输出总奖励为 −1。正确性仍占主要权重，行为项则鼓励搜索后形成可供回答使用的报告。它并不直接衡量材料是否真正相关，因此不能把行为奖励本身当作证据质量。

这一阶段得到的策略，有两个用途：在原串联结构下评测，它就是后面表里的 C-MAS + RL；冻结后，它又成为第二阶段的教师。我们没有另找一个通用大模型给报告打分，而是让一个在相同搜索接口上练过的策略提供反馈。

## 第二阶段，学生走自己的轨迹

团队学生从原始指令模型初始化，而不是从教师权重接着训练。Leader 在训练过程中会不断改变问题拆法，Searcher 遇到的子问题和材料也随之变化。因此，我们需要反馈跟着当前学生访问的状态走，而不只让它模仿一批预先生成好的完整轨迹。

<!-- image:multiagent-opd:images/credit_assignment.svg | 同一问题采样多组团队轨迹。教师在 Searcher 的局部历史上评分学生 token；检索返回和收到的报告不作为接收者生成的动作训练。 -->

具体做法是：学生先运行团队、生成搜索轨迹，教师再读取相同的角色提示、子任务、已检索材料和生成前缀，计算学生所选 token 的概率。教师不会把学生带回自己更熟悉的轨迹，也不需要重新生成一份标准报告，供学生逐字模仿。

这就是这里的 on-policy distillation：样本来自当前学生策略，教师在这些样本实际到达的历史上给出局部偏好。随着 Leader 的分工变化，教师看到的也会是新的子任务历史。第一阶段和第二阶段都让 Searcher 接收问题并返回报告，接口上的一致让这个迁移有了基础。

### 把教师偏好写成 token 优势

蒸馏目标采用学生到教师方向的反向 KL。下面的 mask 只保留 Searcher 生成的 token；检索器返回的材料和 padding 都被排除。

<!-- equation:opd-objective -->

在实际 PPO 更新里，学生采样策略记作 π_old。每个搜索 token 的优势，使用教师与采样策略对同一个 token 的 log-probability 差值，再乘以系数 β。论文中 β 为 0.01。

<!-- equation:opd-token -->

教师认为这个 token 比采样策略认为的更合适时，优势为正，更新会倾向于提高它的概率；反之则降低。这个信号可以覆盖查询生成、过程中的文字和最终总结，不只给整份报告一个统一分数。即使最终答案错误，或者组内结果奖励全部相同，搜索 token 仍可能获得非零反馈。

不过，这不是 token 对最终答案的因果贡献。它表示教师在这个局部上下文中的偏好，教师自身也会有局限。把“更密的过程监督”写成“找到了真正的信用分配”，会夸大这个方法解决的问题。

### 另外两个角色，继续看结果

Leader 的主要目标仍然是团队答对，另加一个有上限的搜索活动奖励。这里统计的是包含至少一个 Searcher 搜索动作的环境步数，计数超过 6 后不再增加奖励，不是简单地给每个搜索子智能体发一份奖励。

<!-- equation:opd-leader -->

Answerer 则按每个候选的正确性学习。Leader 的奖励在同一问题的团队轨迹间归一化；Answerer 的候选奖励在所属 workflow 内归一化。不能因为都叫组相对训练，就把两种比较范围混在一起。

<!-- equation:opd-roles -->

最后把各角色的优势放回各自生成的 token，用 PPO clipped objective 和 entropy bonus 一起更新共享学生。Leader 与 Answerer 的奖励还包含系数为 10⁻³、指向教师的 KL 惩罚；Searcher 已经用 OPD 替换结果优势，不再额外叠加同样的 KL policy loss。

推理时只保留学生，三个角色通过不同提示调用同一个模型，教师不参与运行。共享参数也意味着一个角色的更新会影响另外两个角色：角色分工并没有把模型隔离成三份独立参数。

## 先把评测口径说清楚

实验统一使用 Qwen3-4B-Instruct-2507，接同一个 E5 检索器，每条查询返回 3 段材料。训练数据来自 79,168 条 NQ 和 90,447 条 HotpotQA。训练使用 veRL 与 SGLang，batch size 为 32，每个问题采样 5 条轨迹，学习率为 10⁻⁶，进行 5 次 PPO minibatch 更新。

串联流程允许 5 个环境步，分层流程允许 12 个环境步，后者最多有 5 轮 Leader 分派。比较它们时，需要把结构、训练和运行预算一起看。Prompted Critic 与 MultiAgent-OPD 则使用同样的分层结构和 Leader 目标，主要差别是 Searcher 的学习信号。

测试包含固定的 5,000 个问题，覆盖 NQ、TriviaQA、PopQA、HotpotQA、2Wiki、MuSiQue 和 Bamboogle。每个问题独立运行 4 次，评测时每个回答请求只生成 1 个候选，不能和训练时的 5 候选混用。

- avg@4 是四次运行得分的平均，估计单次尝试的正确率。
- pass@4 是四次中至少答对一次的问题比例，表示覆盖上界，没有附带一个能挑中正确答案的选择器。
- Macro 对七个数据集等权平均，不是把全部问题混在一起算一个总体分数。

最终答案用归一化 Exact Match 判分，缺失或格式错误的答案都算错，不丢弃失败轨迹。去重检查排除了跨训练、开发和测试的规范化同题，但没有证明不存在改写重复或预训练污染。

## 结果提高了，先看提高在哪

| 系统 | Macro avg@4 | Macro pass@4 |
| --- | ---: | ---: |
| C-MAS base | 25.09% | 34.02% |
| C-MAS + RL | 36.07% | 45.97% |
| H-MAS base | 28.60% | 39.32% |
| Prompted Critic | 34.62% | 45.96% |
| MultiAgent-OPD | 38.68% | 48.73% |

没有任务训练时，分层结构比串联结构更好；训练后，简单串联的 C-MAS + RL 又高于 Prompted Critic。这说明“多了一个 Leader”并不自动让训练结果更好，局部学习信号仍然重要。

MultiAgent-OPD 的 Macro avg@4 比 Prompted Critic 高 4.06 个百分点，比 C-MAS + RL 高 2.61 个百分点。相应的配对 95% 区间分别为 [2.98, 5.12] 和 [1.49, 3.73]。这些区间来自对固定模型的测试问题重采样，不是跨多次独立训练得到的稳定性结论。

它在七个数据集上的 avg@4 都高于 Prompted Critic，但不是每个数据集都超过串联教师。例如 NQ 上 C-MAS + RL 为 43.7%，MultiAgent-OPD 为 42.3%；Bamboogle 则从 39.4% 到 46.8%。总体收益不能改写成每种问题都更适合复杂团队。

论文还统一骨干与协议比较了五个 RL 搜索系统。最接近的 Tree-GRPO 为 37.37% Macro avg@4，MultiAgent-OPD 高 1.31 个百分点。这些外部系统只有聚合分数，没有与主要比较相同的逐题配对区间，因此应把它们作为该协议下的描述性比较。

<!-- image:multiagent-opd:images/training_dynamics.svg | 历史验证曲线。横轴是训练步数，不是计算量；每条曲线也不是多次训练的均值。 -->

四次都答对的问题比例也值得看：MultiAgent-OPD 为 29.27%，C-MAS + RL 为 27.05%，Prompted Critic 为 23.24%。覆盖和一致性都提高了，但这些指标仍然没有解决最终该选哪份回答的问题。

## 消融里最值得追的是“不搜索了”

| Searcher 的训练方式 | Macro avg@4 | Macro pass@4 |
| --- | ---: | ---: |
| 完整方法：任务教师 OPD | 38.68% | 48.73% |
| 换成最终答案奖励的 RL | 17.78% | 22.79% |
| 换成未做任务训练的教师 | 29.50% | 40.86% |
| 去掉 Searcher 的直接监督 | 29.82% | 39.86% |

最终奖励版本不只是分数下降，还出现了搜索行为消失：20,000 条测试 workflow 中没有记录到搜索动作，但 99.51% 仍有子任务和报告，99.03% 仍产出最终答案。系统表面上走完了团队流程，却不再从检索器获取证据。

开发集也能看到这个变化。第 300 到 400 步之间，无搜索 workflow 从 0.5% 变为 100%，EM 从 26.0% 降到 21.8%。所以只看完成率会漏掉关键退化；流程能结束，不代表中间仍在做有用的事。

这支持“最终答案奖励在本配置下没能维持检索”的解释，却没有单独隔离所有训练选择的因果作用。各消融保留相同的主要设置，但训练 batch 不相同，不能把单次训练对照写成任何场景都会复现的定律。

另外两行帮助我们拆开问题：保留 OPD、换成基础教师后效果下降，说明反馈来源重要；去掉直接监督也下降，说明只靠 Leader 和 Answerer 的训练不够。后者不等于冻结 Searcher，因为共享参数仍然会被其他角色更新。

## 更好的答案，也用了更多检索

<!-- image:multiagent-opd:images/main_accuracy_cost.svg | 正确率与记录到的推理工作量。Token 统计包含重复历史，不等于延迟、唯一上下文长度或服务账单。 -->

| 系统 | 每 workflow 搜索动作 | 记录的输入 token |
| --- | ---: | ---: |
| C-MAS + RL | 2.86 | 3,886 |
| Prompted Critic | 4.45 | 6,786 |
| MultiAgent-OPD | 5.39 | 9,172 |

相对 Prompted Critic，MultiAgent-OPD 的搜索动作增加 21.4%，输入 token 增加 35.2%，输出 token 则从 885 降到 697。教师虽然不参与推理，学到的学生策略却会改变运行时的工作量，不能据此称为“零成本提升”。

这些记录会在多轮调用中重复计算历史，也没有测量端到端延迟、实际费用或总训练成本。尤其串联与分层流程的步数预算不同，因此更适合把这张图理解为收益伴随的工作量变化，而不是一个已经控制好算力的效率排名。

格式完成也会影响结果。论文做过一个偏向对照方的上界检查：假设把 Prompted Critic 的所有格式失败都修成正确答案，MultiAgent-OPD 的剩余差距为 0.33 个百分点，区间跨过零。那是一个假设修复上界，不能当成实际收益，但提醒我们不要把总分差距全部归给证据推理能力。

## 用一条两跳问题看清接口

可以用一个示意问题理解分工：“某部电影的导演出生在哪里？”这不是论文里的新增实验，只是把接口展开。Leader 可能先让 Searcher 查导演身份，拿到报告后，再让另一个 Searcher 查出生地；也可能在已经知道部分信息时，分派更具体的补查任务。第二轮应该查什么，取决于第一轮找到的证据。

Searcher 能看到的是自己的子问题和局部交互历史，不是一个事后知道正确答案的全知视角。教师也在这个视角下评分。假如第一轮查错了人，第二轮教师反馈仍然是在学生实际访问的历史里计算的；它并不保证替整个团队纠正上游分工。最终结果奖励仍然需要训练 Leader 怎样组织任务，以及 Answerer 怎样使用证据。

反过来，假如某个 Searcher 找对了导演，Leader 却没有把这份报告交给 Answerer，最终奖励可能仍为零。局部教师反馈至少不必随着整个团队失败一起消失。这正是把搜索监督单独拿出来的动机：让中间过程还有可学习的差异，同时保留最终正确性作为团队目标。

## 一个 batch 里，有几种不同的“组”

训练配置里既有每题 5 条团队轨迹，也有每个回答请求 5 个候选。两层采样承担不同工作。前者帮助比较同一问题下不同的协作路径，后者帮助比较给定报告之后的不同答案。把候选答案的得分直接在所有团队之间混合归一化，会改变论文所定义的 Answerer 学习问题。

Searcher 则没有沿用这两种结果优势。它的反馈来自同一局部历史下的教师与采样策略比值，因此不能先把整条轨迹压成一个分数，再复制给每个搜索 token。实现时最好保留 token 所属的角色、workflow、候选与局部调用，让训练侧能够把每个优势值送回正确位置。

还有三份策略需要区分：冻结教师提供比较目标，旧学生负责生成本轮样本，正在更新的学生计算 PPO 的概率比。教师冻结，并不等于学生访问的状态固定；在策略蒸馏的关键恰恰是后者会随着训练变化。只缓存一份静态教师轨迹，复现出来的就不再是这里描述的反馈流程。

## 把格式完成和证据使用分开检查

主要评测严格提取最后一次 Answerer 输出中的答案标签，没拿到合规答案就记零。这个规则让所有失败都进入分母，但也意味着格式控制是任务分数的一部分。论文另用预先选定的宽松规则重新提取保存的输出，检查是否只是格式差异掩盖了正确内容；它不使用标准答案来挑选候选。

这个检查没有改变主评测口径，也没有把所有格式失败都“宽容地算对”。因此，实际宽松提取结果与前面假设的完美修复上界必须分开：前者是重新读取已有输出，后者是假设每个失败都能修成正确答案。两者回答的问题不同，不能只挑一个更有利于结论的数字。

同样，搜索动作被记录下来，也不代表返回的材料有用。记录器区分搜索调用、返回材料、报告和最终答案，才能发现“流程完成但不检索”的问题；继续排查时，还要回到材料相关性、报告有没有保留关键信息、Leader 是否选用了报告。工作量指标是诊断线索，不是证据质量的替代品。

这些检查比只盯着训练 reward 更费事，但可以把退化定位到具体接口。一个看起来不再增长的平均分，背后可能是回答格式、查询生成或信息选择的不同问题。决定是否调整奖励之前，先知道是哪一段行为变了，往往更有帮助。

## 真正需要接好的，是轨迹和反馈

如果复现这套训练，我会先沿完整轨迹检查角色、局部历史、生成 token 和 mask。Searcher 自己写出的报告可以接受反馈；同一份报告被 Leader 收到时，它是观察，不能被当作 Leader 生成的动作训练。教师也必须看到学生当时拥有的材料和前缀，否则比较的就不是同一个决策状态。

第二个检查是归一化范围：Leader 比较团队，Answerer 比较同一 workflow 的候选，Searcher 使用局部教师信号。还要区分学生采样策略、当前更新策略与冻结教师，避免把公式里不同的概率都读成“当前模型的概率”。

这项工作的重点，是把反馈接到更合适的角色和位置。它没有消除教师偏好，也没有证明更复杂的团队总是划算。对需要多轮拆解和搜索的任务，任务训练过的教师可以提供比单一最终分数更细的学习信号；是否值得采用，还要把正确率、搜索是否持续发生、格式完成和实际运行预算放在一起看。
